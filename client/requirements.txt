# client/requirements.txt — chatbot client (host + tool-call loop + UI).
#
# Deliberately separate from the repo-root requirements.txt. That file states
# "the MCP server NEVER calls a chat LLM — no LLM client belongs in this file",
# and the split is what makes that claim checkable rather than a comment: the
# server can be installed and run with no chat-model dependency present at all.
#
# The UI needs nothing. Design document §6 specifies one plain HTML/JS page with
# no framework and no build step, served by `http.server` from the standard
# library, so there is no web dependency to pin here.

# --- Chat model client -----------------------------------------------------
# Talks to the GB10 box's vLLM deployment over its OpenAI-compatible API
# (`topaz-coder` = Qwen3-Coder-30B-A3B-Instruct-FP8). The SDK is the transport
# only — no OpenAI service is involved and no key is required, because that
# route carries no authentication. Point it with CHAT_BASE_URL and CHAT_MODEL;
# the endpoint is explicitly not permanent, so the client checks /v1/models on
# startup and refuses the turn rather than failing four rounds later.
openai==2.41.1

# --- MCP client sessions ---------------------------------------------------
# Same pin as the server so both halves negotiate the same protocol version and
# a client-side change can never silently diverge from what the server serves.
mcp==2.0.0
